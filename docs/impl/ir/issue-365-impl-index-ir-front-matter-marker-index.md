# Issue #365 impl index 生成可能化 — ir front matter 是正・marker 追加・index 再生成

## Summary

`docs/impl/ir`・`docs/impl/exp` の管理 index を `doc-maintenance` の
`index plan` / `index apply` で再生成可能にした。index の source 検証を
落としていた ir 文書 44 件の front matter を impl-doc schema 準拠の形式に
修正し（意味は変更せず）、両 README に generated-index marker を追加して
owner の safe writer（impl-doc `sync_impl_index`）経由で index を再生成した。

## Context

`docs/tasks/issue-365-impl-index-generation.md`（plan:
`docs/plans/issue-365-impl-index-generation-plan.md`、spec:
`docs/specs/issue-365-impl-index-generation.md`、design:
`docs/designs/issue-365-impl-index-generation-design.md`）の実施記録。
変更前の実測では `index plan --dir docs/impl/ir` が source 検証で
rejected（147 件中 44 件が front matter schema 違反）、`--dir docs/impl/exp`
が generated-index marker 欠落で rejected であり、引数なし `index apply`
が exit 1 だった。

## Implementation

### Changes

- `docs/impl/ir/` の 44 文書の front matter を機械的に正規化した。
  行ベースの変換スクリプト（`.tmp-task/fix-frontmatter.js`、一時物・非コミット）
  で以下のみを修正し、本文・ファイル名・id・title・created・owners は不変:
  - `type: "ir"` → `type: "impl"`、`status: "done"/"final"` →
    `"completed"`（完了済みの旧 status 語彙の保守的写像）
  - `updated` の日付+散文を `YYYY-MM-DD` に正規化し、注記は YAML
    コメントとして保持
  - `relations.changes.*` の裸文字列要素を `{type, path}` object に変換
    （拡張子・区切りから file/dir を推定）
  - 欠落していた `relations` ブロック・`changes` 各配列・
    `metadata.experiments.{adopted,rejected}` を補完
  - list 形式の `metadata.experiments` を `adopted` 配列 +
    `rejected: []` の object に変換
  - `updated` 欠落時は `created` の値を使用
- `docs/impl/ir/README.md`・`docs/impl/exp/README.md` を managed 形式の
  最小 stub（手書きタイトル + generated-index marker + Directory 行 +
  空テーブル）に置き換え、`index apply` で owner sync が全行を再生成。
  手書きタイトル（`# Implementation Record Documents` /
  `# Experiment Log Documents`）は preamble として保持された。
- 新規 doc-chain 5 文書と本 IR を追加し、`index apply`（無指定）で
  specs/designs/plans/tasks/test-specs の管理 index も再生成
  （test-specs は既存の status drift 1 件も同時に解消）。

### Decisions During Implementation

- 既存 README の表は行リンクが `[file](file)` 形式で parser が要求する
  `[file](./file)` と非互換かつ手編集禁止の生成物のため、表を保持せず
  空テーブル stub から再生成させた。mergeManagedIndex が preamble
  （タイトル）と tail を保持するため手書き部分は失われない。
- front matter 修正は行ベースの目的別 transformer で実施（YAML パッケージ
  非導入のため）。id/type/status/updated/title/created/owners 以外の値は
  意味を変えない範囲で正規化した。
- IR audit は schema 検証通過後にのみ本文 section 検査を行うため、是正により
  旧形式文書の missing-section error が新たに可視化された。本文変更は
  タスク範囲外のため修復せず、error 総数が baseline を下回ることをもって
  受入とした（319 <= 331）。
