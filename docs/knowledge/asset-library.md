# アセットライブラリと Asset Provider 契約

## 概要

Synvelis の Asset Library は、ローカルフォルダ・現在のプロジェクト・Git リモート・WebDAV といった異なる出所のアセットを、共通の `AssetProvider` 契約の下で browse・stat・pin・open する仕組みである。基盤となる `synvelis-library` クレートは Remote/VCS 依存を持たない独立クレートとして設計され、UI・ProjectStore・Git SDK・Tokio への依存を持たない。検証済み import は `Started→Staged→Verified→Published→Committed` の stage machine で manifest に永続化されながら進み、project への commit は expected revision の CAS に限定される。この領域で最も重要な教訓は、パス名ベースの containment チェック（`canonicalize`+`starts_with`）が component swap の TOCTOU で破られ、root 外オブジェクトの bytes・facts・entries が全経路から漏洩し得るという点であり、恒久修復は Ruviform の handle-relative rooted capability への移行で行われた。

## 詳細

### synvelis-library と AssetProvider 基準契約

`synvelis-library` は Local Folder と Current Project Assets を共通 Catalog として扱う基準経路を提供する。`AssetProvider` trait は blocking かつ `Send + Sync` で、RT や SDK の非公開型を公開 API に持ち込まない。`id`/`kind`/`capabilities`/`browse`/`stat`/`pin`/`open_pinned` を必須とし、`search`/`open_preview` は optional、chunked な `Read + Send` と `FetchReceipt` を返す。

公開型は検証付きコンストラクタとデシリアライズを持つ。`ProviderId`（u128、`"provider-<32hex>"` tagged）、`OpaqueLocator`、`PrincipalId`、`CredentialKey`、`OpaqueCredential`（Debug で credential 値を `<redacted>` にする）、`RemoteAssetRef`/`PinnedAssetRef`/`PinProof`/`RevisionKey`/`ObjectIdentity`/`ContentDigest`、`ProviderCapabilities`/`UnsupportedReason`/`AssetObservation<T>`（Observed/Inferred/Unknown/Stale、`observed_at` で注入 clock を使える）などである。provider 層の `ProviderId`/`OpaqueLocator` は project 側の `AssetId`/`SourceId`/`ImportId` と別型を維持し、偶発的な混同を防ぐ。未対応操作は空集合の成功や黙った近似ではなく、`UnsupportedCapability` と型付き `UnsupportedReason` を返す。

pin の証拠強度は provider ごとに分ける。Local は content-hash の `ConditionalStrong`、Project は `ImmutableObject`、Git blob は `IdentityBound`、Git LFS のみ oid=SHA-256 で `StreamVerified` を主張する。弱い証拠（弱 ETag・branch 名・mtime のみ）は pin 証拠にしない。`OpaquePageCursor` は非空・上限長を検証し、provider・scope・query・principal・epoch に束縛され、失効時は `CursorInvalid`（`RetryAdvice::Never`、再 browse を要求）を返す。未知の sort 値は昇順・降順とも末尾に固定する。`ProviderErrorKind` は NotFound/PermissionDenied/UnsupportedCapability/SourceChanged/IntegrityMismatch/BudgetExceeded/Cancelled/CursorInvalid などの型付き分類で、`ProviderContext` の deadline/budget は協調的であり blocking I/O 自体を preempt しない。

細部の契約も型で固定されている。`digest.rs` の SHA-256 streaming 検証では、空 buffer の `read(&mut [])` は no-op で擬似 EOF しない。`FetchSlot` は端末状態を保持し、結果を `take()` しても `is_finished()` は維持される。`ProviderRegistry` は `ProviderId` と `ProviderKind` の両方を descriptor と照合し、kind mismatch は登録を拒否する。`ProjectAssetsProvider` は `ProjectCatalog` projection と `ProjectBlobStore` port による read-only provider で、`ProjectController` を所有せず注入された read-only projection のみを消費し、token/credential を Project データに保存しない。cursor は project identity と revision に束縛し、`observed_at(cx.now())`・canonical `source_state_name` provenance・`ImmutableObject` pinning を使う。`LocalBlobDir`（project blob store port）は filename-safe 検証の `<dir>/<digest>` open/stat で、`LocalFolderProvider` とは別経路であり、app は `media_root/blobs` を渡して path 規約を複製しない。

### root 外アクセスの封じ込めと rooted capability への移行

`canonicalize`+`starts_with` による check（T0）→ traverse（T1）の 2 段構成では、component swap の TOCTOU により root 外 object の bytes・facts・entries が stat・pin・open・browse の全経路から漏洩し得ることが判明した（N1 containment 欠陥）。破られた不変条件は「root 外 object の bytes/facts/entries は如何なる経路からも返さない」である。post-open の `is_file()` 再検査は type のみを保証し、swap 後に FIFO/device を指した場合 `File::open` 自体が block し得る残存 DoS であり、遮断済みではなかった。streaming SHA-256 検証は content の正しさを保証するが、どの object を読んだかの containment を代替しない。`VerifyingReader` は EOF 到達前に読み取り byte を caller へ返すため、out-of-root file の bytes が `open_pinned`/`open_preview` で届き、`pin` は out-of-root file の sha256+size を返す content disclosure oracle になっていた。

恒久修復は Ruviform `ruviform-io-file::rooted` の handle-relative capability（`RootedDir`/`RootedFile`/`open_regular`/`read_dir_each`/`open_scoped_root`）への移行で行い、Synvelis 側に unsafe・OS 呼出の重複・`cap-std` を置かない方針とした。SV 側での自前実装が不可能と診断された根拠は、std の `MetadataExt::file_index`/`volume_serial_number` が unstable（rust#63010、pinned toolchain 1.99.0 でコンパイル不可）、Win32 `CreateFile` に `OBJ_DONT_REPARSE` 相当がない、handle→path が std 非公開、workspace が `unsafe_code = "forbid"`（`#[expect]` でも解除不可）で FFI lint ゲートを通過しない、という制約である（synvelis#85、ruviform#398/#409）。

移行後の構造は次のとおりである。`LocalFolderProvider` は `RootedDir`（`rooted_options()`: max_depth 256 / max_components_total 2048 / max_open_dirs 256 — 旧 canonicalize 経路の実質 acceptance を下回らない有限 bound）を保持し、locator は `RelativePath` で検証する。`stat` は `metadata(WithinRoot)` 一回、`pin`/`open_preview`/`open_pinned` は `open_regular(WithinRoot)` 一回の verified open で、`RootedFile`（`Read+Seek`）と `NodeInfo` が同一 opened object を記述する。stat→open の 2 段構成は消滅した。FIFO/device/link-under-NoFollow は `open_regular` が open 前に `NotRegularFile` で拒否し、blocking open に到達しない。`LocalBlobDir` は呼出毎に store `RootedDir` を開き、`metadata`/`open_regular(WithinRoot)` で同一 object の facts+reader を返す。SV 側の filename-safe/DOS device 検証は維持される。

handle authority の意味論も重要である。scoped directory handle は取得時点の object を address し続け、外部 rename でも読み取りを継続する（pathname 継続包含ではなく handle authority）。root rename+同一 pathname 別 tree 設置でも held tree を serve し、replacement（別 object）は列挙されない。このため pathname 再 open + `NodeId` 照合による `SourceChanged` 拒否は正規契約では不要な補償として撤去された。`WithinRoot` は canonical-root component の lexical prefix で absolute link target を判定するため、`/var` vs `/private/var`・8.3 名・`subst` drive 等の非 canonical alias は kernel 上 in-root であっても `EscapesRoot` を返し得る。これは RF の文書化された保守的縮小であり、SV が隠さない。

`read_dir` の全件 `Vec` materialize は列挙段階の memory/work bound と cancel/deadline を不可能にする問題があった。`read_dir_each`（callback 列挙 + `EntryFlow::Stop`/`EnumerationOutcome`）で kept window（`remaining+1`、旧 `take(remaining+1)` と同じ enumeration order prefix）を visitor 内収集→sort する方式により、emit/subset 意味論を同値のまま列挙の memory/work bound と cancel/deadline の列挙段階適用が回復した。scope の公開 `base` prefix は、scope の handle-derived canonical を held root の現在の handle-derived canonical（`open_scoped_root("")` で再 anchor）から strip して求め、両辺 handle 由来のため root rename 後も canonical-relative を維持する。prefix 不成立は `PermissionDenied` で fail-closed。

`RelativePath` 文法は旧 `parse_locator` より厳格で、Windows 予約名・空白端・末尾 `.`・255B 超 component・制御文字・非 UTF-8 を `InvalidInput` で拒否する。該当名の object は locator では恒久にアクセス不可で、browse では unaddressable として partial skip される。trailing `/` は directory marker として受理する（acceptance 拡大で同じ object を指す）。browse の link 処理では、範囲内 dir link を `Container`+`via_symlink` で表示するが下降は実 dir のみに限る（link target は canonical 実 path 側で必ず列挙されるため出力 entry は同値）。escaping/dangling link entry の facts は link 自身の最小 facts（`Symlink` kind + NotProvided）を返す。旧実装は follow した target の facts を報告しており containment 外の情報流出だったため修正された。dangling symlink は Windows/Unix で `Missing` に統一した（旧 Unix 経路は entry を黙って skip しており、test-spec の `Missing` 契約は Windows でしか満たされていなかった潜在不整合の修正）。dir entry の `byte_len` は `NotApplicable`（`NodeInfo` は dir に length を持たせない。旧実装は dir size を報告していた）。

`FileErrorKind`→`ProviderErrorKind` の型付き対応は、`EscapesRoot`→`PermissionDenied`、`Unsupported`→`UnsupportedCapability`、`IdentityMismatch`→`SourceChanged`、`NotRegularFile`/`NotDirectory`/`InvalidInput`/`LoopDetected`→`InvalidRequest`、`LimitExceeded`→`BudgetExceeded`、`Io` は source の `io::ErrorKind`（`NotFound`/`PermissionDenied`/その他 `TransientIo`）で精緻化する。loop/budget 拒否は決定的なので retry を唆す `TransientIo` に畳まない。browse DFS は未訪問 dir の scoped handle を stack に保持し（`max_entries`/`max_open_dirs` で bounded、枯渇時は `truncated` で fail-honest）、旧 canonical-path visited set は `NodeId` 集合へ置換された（mount/bind alias 用の loop guard として温存）。pin は `ConditionalStrong{ContentHash}` の content pin 契約を維持し、object-identity `NodePin` は契約上の pin 証拠ではなく、weak identity FS への追加制限も課さない。残存する制約として、hard link（同一 object ゆえ name ベース containment の許容内）は変わらず残存し、`RootedDir::open_with` の path→capability 境界には RF 文書化の residual race（backend が handle-derived canonical を提供しない場合の `fs::canonicalize` fallback）が残る。真の rooted-open 強化が必要なら RF 側の責務として起票する。

レビュー上の教訓として、N1 は 3 ラウンドの review-protocol で当初 Low-Medium と評価されたが、独立 Reviewer A/B + Validator で CONFIRMED、coordinator Judge が P1 BLOCKING と判定した。初期評価コメントは「影響は `open_preview` の out-of-root regular file 読み取りに限定」「`is_file()` 再検査により非 regular の読み取り/DoS は遮断」と誤っており、後に訂正された記録が残る。実 race（並行 swap）は未測定で、観測は deterministic fault barrier 注入によるものである。Unix は未実測（開発/CI 実測は Windows）で、当時 `synvelis-library` は app crate へ未配線で利用経路がなかった点も重大度評価とは別論点として記録されている。

### Verified Import パイプライン

import パイプライン（PR #220、squash `929a5e9` で merge、`src/import.rs` 約 1.8k 行）は `Started→Staged→Verified→Published→Committed` の stage machine を各遷移で manifest に永続化する。manifest write は `StagedFile`+`PublishMode::Replace` による atomic write である。`stage_source` は 64 KiB 固定 chunk の bounded streaming で、incremental SHA-256 と byte-length を計測し、chunk 毎に `check_interrupts`・byte budget・pin 期待 digest/size 照合・provider completion-slot 交差検査を行う。`verify_staged` は staged bytes の readback 再計測を manifest と照合する。

`BlobPublisher` port と `StagedBlobPublisher`（`PublishMode::CreateNew`、`FileAndDirectorySync` の正直な `Unsupported` fallback、publish-temp readback verify、seal 前の integrity gate）を持ち、publish は三値を返す。`Published`（post-failure verify）、`Indeterminate`（stat reconcile + 単一 retry → `PublishIndeterminate`）、`NotPublished`（typed failure）である。`DirectorySync::{Supported,Unsupported,NotRequested,Failed,Unknown}` は観測値のみを記録し publish 成否と分離する。`Indeterminate` reconcile は stat + 単一 retry とし、2 連続 indeterminate は `PublishIndeterminate` で停止して手動 `inspect_imports` を要求する意図的な停止点で、自動収束しない。

`CommitVerifiedImport` `Operation` は manifest 固定の `expected_project_revision` で asset+source+applied-import（+任意 clip）を単一 atomic apply する。予約 ID の reseed/衝突検査・lane/track/clip 契約検証を行い、`import_id` 予約は durable reservation floor 超過が必要（manifest-less dir 保護）。`rebase_import`（stale 解決のみ）・`inspect_imports`・`gc_orphans`（project+manifest reachability、foreign/legacy 非触）を提供する。`Source` は `SourceState::Imported` で commit し、byte integrity のみを検証して media decode 検証は consumer の `SetSourceState` 責務に残す。`CommittedLive` は `SavedRevision`/`HEAD` を意味しない（`saved()==None` を test で assert）。scripted `BlobPublisher`/`AssetProvider` double は fault *分類* の証拠であり実 durability 証拠ではなく、実 publish は ruviform `StagedFile`/`SealedFile` primitive 経由で独自 atomic rename/durability の再実装はしない。

commit 相の cancel 契約は、publish 完了〜`controller.apply` 間に cooperative cancel を観測できないのは契約違反と判断し、`apply` 直前に最後の `cx.check_interrupts()?` を 1 箇所だけ置く（blob re-stat の後・`commit_op`/`controller.apply` の前）。`apply` 成功後は commit が事実なので `Cancelled` を返さない。`apply`〜manifest 書込みの crash は既存 `applied_replay` が reconcile する。blob namespace は additive で、`LocalBlobDir::object_rel` に `sha256:<64hex>` → `sha256/<hex>` の `RelativePath` 写像を追加した。旧 flat 名前空間は不変・衝突不可で、CRC collision の 2 asset は別 identity・非 content-addressed のまま共存する。

### v5 snapshot 互換と digest 分類

v5 snapshot 互換は ALIB-02 の deferred stub `alib-02-v5-snapshot-compat` として spec/design/plan/task/test-spec の doc chain ごと分離された経緯がある。`AssetDigest`/`DigestKind` の型付き分類層を `synvelis-project` に追加し、digest 文字列は lossless（書き換えなし）で、分類境界は `validate_references` に集約する（全 asset/source/applied-import の digest 文字列（空・不正形式拒否）と receipt→live entity 参照を検証）。STEPS ladder に v10→v11 step を追加し、`SCHEMA_VERSION` は 10→11→（後続で 13）へ進んだ。

`CommitVerifiedImport::validate` に `AssetDigest::is_content_addressed()` ゲートを追加し、非 SHA-256 の content digest による verified commit を拒否する。旧 snapshot が空 digest を含む場合 load が新たに失敗し得るが、「不正 digest は拒否」が受入条件でありテストで固定された。`AssetDigest::parse` は CRC16-hex を受理する fail-open 分類で、`kind()==Crc32Fold`→`is_content_addressed()==false` が verified 昇格を構造的に防ぐ設計であり、「受理して弱く分類」が正しい挙動である。fail-closed 分類の追加は不採用とし、空文字列のみ `validate_digests` が拒否する。劣化語彙は既存 `snapshot/` 型（`ContentStatus`/`SnapshotValidation`/`SnapshotCompleteness`/`SnapshotError`）を使い、Missing/IntegrityDegraded/ReadOnly/Reject の重複 enum を新設しない。`migrate_v5_routing` の意味は変更しない制約を遵守した。

実 v5 fixture slice（PR #328）では production code 追加が不要と実測で確認された。既存 STEPS ladder・`snapshot/` resolver・`AssetDigest`/`DigestKind` 分類・controller の revision bump が受入条件をすべて満たしており、不足は「実 v5 bytes による証明」のみだった。v5 fixture は v5-era build（commit `a401e5c`、`SCHEMA_VERSION=5`）の実 serializer 出力で、現行 tree からは再生成できない。generator（`emit_v5_fixture.rs`）は detached worktree でのみビルド可能であり、fixture 喪失時の再現はこの経路に依存する。

### Git Remote Provider と selective fetch

Git provider は read-only の `AssetProvider` 実装で、immutable Commit/Tree object を対象とし、mutable ref は各呼出で具象 commit sha に解決する。pin は `PinProof::ImmutableObject`（`commit:<sha>`）で、blob identity は `git-blob:<oid>`、Git LFS は `git-lfs:<sha256-oid>` である。Git object id（SHA-1/SHA-256）は `ContentDigest` ではなく `ObjectIdentity` scheme で分離し、blob pin は `IdentityBound`、LFS pin のみ `StreamVerified`（oid = SHA-256）を主張する。

selective fetch は `git clone --mirror --no-checkout --filter=blob:none` の derived bare mirror 上で `cat-file` の promisor lazy fetch に委譲する。`--mirror` clone は一度だけ、`fetch --prune` は明示 refresh のみで、Project VCS state・working tree・index・HEAD は一切変更しない。mirror は derived cache で全喪失は再 clone で回復する。LFS pointer は metadata であり、`pin`/`open`/`preview` の全経路で pointer text を content として serve しない。実 object は SHA-256 と宣言 size で検証してから fetchable で、pointer-shaped blob で `check-attr` が失敗した場合は LFS 側に fail-safe 判定する。

`--filter` silent ignore の教訓がある。`file://` transport は `--filter` を warning のみで無視して成功するため clone exit code では検出不能である。mirror config の `partialclonefilter`（要求の有無）と object census（`rev-list --missing=print` + `for-each-ref`/`ls-tree -r` の has-blobs 判定、実際に partial か）を分離して判定し、両者を分けて `Reject` policy では `UnsupportedCapability` を返す（`AllowFullMirror` のみ full mirror を明示許容）。selective fetch の粒度限界として、`ls-tree -l` は列挙 blob の lazy fetch を引き起こすため、selective の保証は「browse した tree 直下」までであり、未 browse の subtree blob は promisor-missing のまま残る。`ls-tree -z -l` parser は size column の空白 padding を whitespace run 分割で許容する必要がある。

Git 呼出は `std::process::Command` の固定 argv・prompt 無効・credential env 注入で行い、依存追加なし（Cargo.toml/Cargo.lock 不変）である。stderr→`ProviderErrorKind` 分類と diagnostic の secret redaction を実装し、`read_to_end` は std が `ErrorKind::Interrupted` を retry するため mid-stream cancel の typed 検証は `read` + completion slot で行う。ambient global git-lfs 設定（template hook・`filter.lfs.*`）は fixture-local config で無効化して fixture を決定的にし、committed `payload.bin` が pointer text verbatim であることを self-check する。git 非存在時は fixture が `Option`/`None` を返し test は明示 skip する（NotRun を Pass にしない）。Windows 固有の落とし穴として、`TempTree` canonicalize の `\\?\` verbatim prefix を git path 引数が拒否するため `plain_dir`/`plain_path` で除去が必要で、git-for-windows は `:` 入り filename を U+F03A に変換するため fixture から除外した（locator 文法の `:` 合法性は unit test で担保）。mirror HEAD unborn（`--mirror` clone）対策として `reference="HEAD"` は `ls-remote --symref` で remote HEAD 解決し、既定は明示 ref 推奨を docs に記載した。

`GitRemoteUrl`/`GitRemoteScheme` は scheme allowlist（file/http/https/ssh/git + scp-like SSH + local path→`file://` 正規化）で、`ext::`/`fd::`・password userinfo・非 SSH userinfo・malformed scp-like を拒否し、credential は URL に埋め込まない。locator 文法は `<rev>:<path>` で、rev は安全な ref 部分集合、path は traversal・空 component・`\`・制御文字・過長を拒否する（`:` は path 内で合法で、git 自体が最初の `:` で split）。`GitRemoteProvider` は browse/stat/pin/open_pinned/open_preview を持ち、`GitRemoteConfig`/`GitProviderInfo`/`UnsupportedFilterPolicy`/`GitRemoteScheme`/`GitObjectFormat`/`MirrorMode`/`LfsBackendKind` を公開し、`git_info()` で mirror mode・object format・LFS backend を正直に公開する。cursor は JSON payload に provider/scope/query/principal/epoch/offset fingerprint を束縛し、search は provider-side index 非保有で `UnsupportedCapability` を返す。huge blob の pin 時 lazy fetch は `max_bytes` で pin 前に `BudgetExceeded` となり、object 単位の選択取得であり repo 全量ではないことを spec に明記した。

### Git LFS remote fetch（batch API）

`synvelis#331` で `LfsBackend` に `RemoteHttp { remote, credential_key }` variant と `LfsBackendKind::RemoteHttp` を追加した。backend 選択は、`remote.lfs_objects_root()`（`file://`）は従来どおり `Local`、`GitRemoteScheme::Http` は `RemoteHttp`、それ以外（`ssh`/`git`/`Other`）は `Unsupported` で、synvelis#521 の slice で `Https` も `RemoteHttp` に追加された。`file://` の local `lfs/objects` 経路は `open_local` として無変更で温存し、SSH・`git://` は socket を開かず typed `UnsupportedCapability` を返す。

endpoint 解決は git-lfs server discovery の clone-URL 規則に従い、remote path が `.git` 終端なら `<path>/info/lfs`、それ以外は `<path>.git/info/lfs` を endpoint として `/objects/batch` を POST 先とする。`lfs.url`/`remote.*.lfsurl`/`.lfsconfig` override は provider に repository-config 供給源がないため参照しない。batch request は `POST` で `Accept`/`Content-Type` とも `application/vnd.git-lfs+json`、body は `{"operation":"download","transfers":["basic"],"objects":[{"oid","size"}]}`。`transfers:["basic"]` 固定で custom transfer（`lfs-standalone-file` 等）の negotiation を行わず、`actions.download` が返らない server は `InvalidRequest` で fail-closed とする。

batch response は 1 MiB cap で bounded read し、serde で `hash_algo`/`objects[].{oid,size,actions.download.{href,headers},error.{code}}` を parse する。`hash_algo` が `sha256` 以外なら `UnsupportedCapability`、object 照合は request 順ではなく `oid` 一致検索（spec は順序を保証しない）。per-object `error.code` を size/action 整合チェックより先に authoritative として処理し（HTTP status と同じ番号体系で `status_error` に写像）、`message` は server free text が署名 URL 等を含み得るため model 化せず error detail にも出さない。

download href 解決は `http(s)://` 絶対 URL・protocol-relative `//host/…`・絶対 path・relative reference を受理し、非 HTTP scheme は `UnsupportedCapability`（socket を開かない）。relative は remote origin root `/` 基準で解決する（batch API path は API endpoint であって resource namespace ではないという解釈）。fragment は送信せず、path は厳密 percent-decode、query は raw のまま保持する。`expires_in`/`expires_at` は助言的 metadata として扱い href をそのまま使い、期限切れは GET の typed HTTP error として顕在化させる。download GET では action `headers` を string value のみ verbatim 付与し（wire 境界で header name/value を再検証し不正なものは drop — request smuggling 経路を塞ぐ）、redirect は最大 `MAX_REDIRECTS` まで follow し、303 および POST への 301/302 は GET に rewrite、307/308 は method/body を保持する。redirect chain の各 hop で origin を跨いだ follow を許可するが credential 付与不変条件で漏洩を防ぐ。`Content-Length` early check は declared size との一致のみ検査し、欠落・chunked は streaming verifier に委譲する。EOF の SHA-256 `VerifyingReader` が authoritative である。

credential 境界は、`credential_key` を fetch 毎に `ProviderContext.credentials` から解決し `Authorization` header 値としてのみ使用し、付与は target origin が git remote origin と一致する場合のみに限る（署名付き cross-origin CDN href には絶対に付かない）。action-supplied `authorization` は上書きせず、URL・error detail・batch body に secret を出さない。HTTP status は `status_error` で写像し、401→`AuthExpired`、403→`PermissionDenied`、404→`NotFound`、405→`UnsupportedCapability`、409/5xx→`TransientIo`、412/416→`PreconditionFailed`、429→`RateLimited`、その他→`InvalidRequest` とする。oid 形式不正・batch JSON 不正・size/action 不整合は `InvalidRequest`、pointer が宣言しない `expected_size=None` の remote fetch も `InvalidRequest`（batch API の `(oid,size)` pair が必須のため）である。

共有 HTTP 層の再利用パターンとして、ALIB-06 の `webdav::http`（最小 blocking HTTP/1.1、`std::net::TcpStream`、依存追加なし）を `HttpEndpoint`/`send_endpoint`/`HttpRequest.query`（verbatim 送出 — 再 encode は署名 token を壊すため request line 直前で control/`#` を拒否する fail-closed 検査付き）の内部一般化で `pub(crate)` 共有層化し、Git LFS が再利用した。`https://` remote は当初 `UnsupportedCapability` だったが、synvelis#521 slice で rustls + `TlsTrust`/`ProviderContext::tls` seam（`ProviderErrorKind::TlsVerification` 追加）により `RemoteHttp` backend として実装済みである。`MockTlsServer` fixture で検証し、実 HTTPS endpoint・実 remote は引き続き NotRun である。

### WebDAV Provider

WebDAV provider は依存追加なしで `std::net::TcpStream` 上の最小 blocking HTTP/1.1 client（`webdav::http`）と自前 XML pull parser（`webdav::xml`）を実装した。`WebDavProvider`/`WebDavConfig`/`WebDavProviderInfo`/`WebDavScheme`/`WebDavUrl` を additive re-export し、Cargo.toml/Cargo.lock/mise.toml は不変である。`webdav::xml` は multistatus subset 用 streaming pull parser で、entity/CDATA/comment/PI/namespace-local 名対応・strict UTF-8・depth/byte/text 上限を持ち、malformed input は fail-closed で拒否する（対象外の XML 構造を含む server 応答も拒否される）。`https` は parse 可能だが TLS stack 非保有のため connect 時に typed `UnsupportedCapability` を返し、silent downgrade はしない（TLS 対応までは `https` WebDAV は利用不可だった）。

metadata-first で、`PROPFIND`（browse Depth:1、stat/pin Depth:0）で listing・fact 収集を行う。propstat は `200` のみ採用し、`resourcetype` の `collection` で container 判定、missing/foreign/unaddressable href は skip して partial coverage に計上し、entry 数・body byte 上限で打ち切る。pin は strong ETag のみ `PinProof::ConditionalStrong` + `StrongValidator{IfMatch}` で結び、weak（`W/`）・missing ETag は `UnsupportedCapability` で fail-closed とする（ETag を返さない・weak ETag のみ返す server では pin/open_pinned が利用不可）。ETag は validator であり digest ではないため `digest_hint`/`checksum_hint` に載せない。`open_pinned` は `If-Match` 条件付き GET + 応答 ETag 独立照合の二重化で、不一致→`SourceChanged`、412→`PreconditionFailed`、404→NotFound/RevisionGone とする。pin/conditional read の revision 強制は server 側 `If-Match` に委譲し、client は応答 ETag の独立照合で `SourceChanged` を検出する。weak ETag は RFC 上 `If-Match` に使えないため受理せず、ETag header injection 対策として validator を ASCII entity-tag grammar で fail-closed 検証してから `If-Match` に載せる。

WebDAV に真の paging は存在しないため、browse は entry/byte budget で bounded listing とし打ち切りを `Coverage::Partial` として正直に報告する。cursor は provider/scope/query/principal/membership fingerprint 束縛で changed collection を `CursorInvalid` で拒否し、search は server-side index 非保有で `RequiresIndex` 宣言的 unsupported とする。preview の `Range` 要求で `206`+`Content-Range` を検証し、server が range を無視した `200` は bounded client-side skip（range 対応済みとは主張しない）、`416` は empty read とする。`BoundedReader` は cap ちょうどの body を EOF と誤認しないよう cap+1 byte を probe し、超過は `BudgetExceeded` とする。response head 読み取りで先読みした body 先頭バイトを失わないよう `ResponseHead.pending` で body reader に引き継ぎ、body は `Content-Length`/chunked/close の 3 系統を `BodyReader` で系統別に実装して protocol 違反・mid-transfer disconnect を typed error で返す。socket stall 中の cancel/deadline 不応対策として短い read timeout slice の retry loop で約 50ms 毎に cancel/deadline/io_timeout を確認する。

credential は call 毎に `ProviderContext.credentials` から解決し `Authorization` header のみ送出し、secret は URL/locator/error/log に出さない。redirect は same-origin のみ follow（cross-origin は接続前拒否、303 は follow せず typed error、上限あり・loop 検出）で、host は parse 時 lowercase 正規化（RFC 3986）する。`WebDavUrl`/`WebDavScheme` は `http`/`https` + authority のみ受理し、userinfo・query・fragment・path（`/`のみ許容）・malformed port・empty/non-ASCII host を拒否し、default port は canonicalize、IPv6 literal（`[::1]`）に対応する。locator は decode 済み absolute server path で、`normalize_path` が leading slash 1 本・末尾 slash なし（`/`のみ例外）・`.`/`..`/空 component/`\`/制御文字/NUL/過長を拒否して `root_path` confinement を強制する（`/music` と `/musical` を混同しない境界一致）。`href_to_path` は absolute/absolute-URI/scheme-relative/relative href を解決し percent-decode は厳密に 1 回、dot-segment は構造的に除去する。`getlastmodified` は IMF-fixdate/RFC850/asctime の 3 形式 parse で失敗は `Unknown{Other}`（捏造しない）。HTTP status → `ProviderErrorKind` 分類（401/403→auth/permission、404→NotFound/RevisionGone、412→PreconditionFailed、429→RateLimited、5xx→TransientIo 等）を行い、read は `ProviderLimits.max_bytes` で bounded、oversize は verifying reader/completion slot 経由で typed failure とする。

### Browser/Import UX（headless slice）

ALIB-05 は headless slice として `synvelis-workspace::library_ui`（約 3000 行の `LibraryViewModel`・`LibraryViewState`・`LibraryAction`・wire DTO（`ProviderWire`/`BrowseEntryWire`/`StatWire`/`ImportTargetWire`）・surface state（`PinUiState`/`PreviewUiState`/`ImportUiState`/`DragUiState`）・`LibraryFault`/`LibraryReason`・`LibraryImportPorts`・`LibraryBackend`/`LibraryViews`・`library_spec` → `ViewSpec` projection）と `synvelis-app` の `syn.library.providers`/`visual`/`view`/`action` 4 op を実装した。browse（opaque cursor paging）・coverage・search・stat・pin・preview plan/fetch/cancel・verified import（`import_verified`/`rebase_import` + `ProjectController`）・drag ghost を typed state として投影し、unsupported/offline/missing/stale/cancelled を empty・成功・generic error に collapse させない。HEADLESS ONLY であり、実 GPUI mount（synvelis#114）・実 provider/network/credential（synvelis#91）・v5 real-data import（synvelis#86）は対象外である。

op surface は、`syn.library.providers`（backend 未 bind でも空 list、捏造しない・view 不要）、`syn.library.visual`（`ViewType::AssetLibrary` を adopt した open/close）、`syn.library.view`（deterministic 投影・typed state verbatim）、`syn.library.action`（`LibraryAction` に verbatim decode）からなる。action tag は `provider.select`/`browse.refresh`/`browse.scope`/`browse.more`/`search.set`/`search.clear`/`entry.select`/`entry.stat`/`entry.pin`/`preview.plan`/`preview.fetch`/`preview.cancel`/`import.submit`/`import.rebase`/`import.retry`/`import.dismiss`/`drag.begin`/`drag.drop` の 18 種で、malformed params・未知 tag・未登録/wrong-kind view・unbound backend は typed `ErrorBody`（`invalid_params`/`unavailable`）を返す。

設計上の決定は 4 つの実験（E1〜E4）で全て採用された。wire DTO は `synvelis-library` の型付き値（`AssetObservation`/`Availability`/`EntryFacts`/`ProvenanceRecord`/`ProviderCapabilities`）を serde で verbatim 埋め込み、flatten しない（flatten すると `unknown{reason}`/`stale{reason}` の reason payload が失われ driver 側で復元不能になるため）。`LibraryAction` は internally-tagged serde enum（`#[serde(tag="action")]` + `deny_unknown_fields`）で wire params を variant field へ直接 decode し、action-level failure は `state.fault`/surface state に着地させ op error と混ぜない。mutating action は対象 locator を明示し ambient selection を暗黙 target にしない。唯一の例外は `preview.fetch` の `locator` が `Option` で selection fallback を持つが、spec button は常に locator を明示 emit するため ambient target 化は投影面では起きない。`syn.library.*` op は service thread 同期実行（`syn.vcs.*` と同じ discipline）で、preview read loop は chunk 間で協調 `CancellationToken` を見るため、後続の `CallOutcome::Job` 化で mid-flight cancel を contract 変更なしに載せられる。import は `WorkspaceManager::with_library` の split borrow（`&mut LibraryViews` + `&mut ProjectSession`）で `LibraryImportPorts`（借用 `ImportStore`/`ProjectBlobStore`/`BlobPublisher`）と `ProjectController` を同時に渡し、`Arc<Mutex>` 共有を避けて唯一の project mutation 経路を expected revision CAS に限定する。

`import.submit` は submit 前に provider `pin` を明示実行し `ImportIntent{import_id, expected_project_revision, source: PinnedAssetRef, target}` を構築する。`import_id` は `(provider, locator)` の FNV-1a hash（`import_template_id`）で埋め、hash アルゴリズムを固定して provider 間衝突を避ける。同一 asset の再 submit は `reused` 冪等 replay、異 asset は `IntegrityConflict` に衝突しない。pin の `expected_size` が whole-object consent 閾値超過なら `allow_full_object` 必須である。verified import の project commit は `ProjectController::apply` 直通で `ProjectSession::apply` の engine/control 通知を迂回するため、op 層が action 前後の revision を比較し実際に進んだ場合のみ `notify_committed_change()` を呼ぶ（冪等 replay・typed failure では通知しない）。`provider.select` は provider-bound state を全破棄するが `CommittedLive` receipt は project truth として残す。`search.set` 失敗時は search mode に入らず既存 listing を browse label のまま保持し、`browse.refresh`/`browse.more` は search mode 中は `SearchQuery`（同一 cursor・scope・text）を継続する。`LibraryViews` は model を lazy materialize し、backend bind 済みでも要求された view にのみ model を作り、provider catalog を model 内に捏造しない。

既知制限として、`import.submit` は一部の `ImportError`（`Io`/`Corrupt`/`PublishFailed`/`JobState`）を `ImportUiState::Failed{reason:"internal"}` に丸める（`IntegrityMismatch`/`CommitRejected`/`PublishIndeterminate`/`Provider`/`StaleRevision`/`IntegrityConflict` は typed。細かい typed 回復は `syn.library.jobs` slice の責務）。`ProviderContext` は principal のみで budget/deadline/credential 未配線（実 provider 配線で `LibraryBackend` 拡張が必要）。preview は `provider.open_preview` 直読みで `LibraryCache` 経由ではなく、`Ready{cached:false}` 固定はこの制約の正直な反映である。全 op が service thread 同期で長時間 fetch が thread を占有し得る（`syn.vcs.*` と同じ既知制約）。`library_ui.rs` は view-model・action・wire DTO・ViewSpec projection・registry を単一モジュールに収める（約 3000 行）構成で、責務は型で分離済みだが、実 provider 配線・`syn.library.jobs` ledger・`CallOutcome::Job` 化で拡張する際に分割を検討する余地がある。

### Catalog/Preview Cache の設計方針（計画段階）

ALIB-03（synvelis#87）の cache は非正本の derived store であり、project media・verified blob・import manifest とは別物で、cache 全喪失は miss→provider 再取得で回復する設計である。secret/生 token は key・disk・event に出さず、disk path の principal 成分は SHA-256 全桁 hex fingerprint のみとする。`CommittedLive`/`SavedRevision` の区別は ALIB-02 を踏襲し、cache は save/HEAD に一切関与しない。

計画段階の設計要素は、cache 側に `CachePolicy`/`CacheStats`/`CacheLease`/`StoreState`(Mutex)/atomic payload write/LRU+TTL eviction/lease 保護/single-flight/`retire_principal`/`credentials_changed`/`clear`/`stats`/`LibraryCache` facade、catalog 側に `CatalogGeneration`/`CatalogQuery`/`CatalogCacheKey`/`IndexCompleteness`/`CatalogIndex` record/`IndexStatus`/cache cursor（encode+decode+key/build 照合）/`browse`/`search`/`index_status`（hit/refresh/stale/offline-cached/permission-denied retire）、preview 側に `PreviewFormat`/`PreviewRequest`/`PreviewCacheKey`/`PreviewMeta`/`PreviewLease`(Read+cancel)/`preview_plan`/`preview`（pin→key→hit|bounded stream→staging→atomic publish→lease）、notify 側に `LibraryEvent`/`LibraryEventKind`/`RetireReason`/`LibraryEventSink`/`SuppressingSink`/`RtEventQueue`(try_lock+bounded+alloc-free) である。RT lane の alloc-free 検証には `stats_alloc = "0.1.10"` dev-dep を使い、`RtEventQueue::emit` の warm 後 alloc/dealloc 0・非 blocking・bounded drop を `tests/rt_cache.rs` で検証する方針だった。

重要な注意点として、本グループの文書では ALIB-03 の IR が存在せず plan/task は in-progress のままであり、実装完了の実績はこの文書群からは確認できない。cache の非正本性・principal fingerprint・single-flight・RT alloc-free 検証方針は計画段階の記述であり、実績としては未確認である。

### 運用・プロセス上の知識

canonical 検証入口は `mise run`（fmt-check/check/lint/test/build/test-rt/test-msrv）で、worker 並列環境では `CARGO_BUILD_JOBS=2` で重い build の並列を制限する慣行がある。cargo 直接実行は補助証拠であり mise exit を正規結果とする。`mise run test-msrv` の扱いには揺れがあり、POLICIES §5 で Daily Full CI 委譲のため NotRun 記録可とする slice と、実走して Pass を記録する slice が混在する。`cargo-platform@0.3.3` が rustc 1.91 を要求して MSRV 1.89 で fail した main 由来の不整合があったが、merge 後 lock で解消済みである。

`docs/*/README.md` の managed index は `doc-maintenance index apply`・`sync_impl_index` で再生成し手編集しない。新規 doc は merge 時の index 再生成まで `index-missing-entry` finding を持つ既知の一時状態で、Coordinator が merge 時に再生成する運用である。doc 監査は `doc_status.js lint`/`audit`・`audit_impl_record.js`・`audit_experiment_log.js`・`audit_docs.js --type all` で、新規 finding を増やさないことが判定基準であり、repo 全体に legacy invalid-id 系・broken relation・reciprocal warning の既存 baseline finding があるため、既存不具合の修復はスコープ外とする扱いが繰り返される。並行 worker 運用では同 repo で複数 worker が稼働するため占有リスト（ownership）を定め、`git diff --stat` で占有リスト外の変更がないことを最終確認し、merge 前に `git fetch origin main && git merge origin main` で最新 main を取り込み生成物を再生成・再検証する。

Ruviform 依存は既定ブランチ追従の git dep で解決 rev は `Cargo.lock` に記録する（rev pin なし・vendor なし・SHA 固定禁止）。`check-ruviform-rev` の REV 不一致は `ui/vendor/ruviform` の stale vendor を検出する fail-closed で、復旧は `mise run sync-ui-deps` の再実行である（synvelis#230）。review-protocol は Reviewer A（協調）+ Reviewer B（敵対）→ Validator dedup → Judge の流れで、CONFIRMED blocker 0 件を ACCEPT 条件とする。実装系 slice はほぼ全てこの protocol を通過済みである。

fault 注入の再利用可能パターンとして、scripted provider/publisher double（`ScriptedProvider`/`CancelOnEofProvider`/`CancelAtEof`/`ScriptedPublisher`/`DirSyncUnsupportedPublisher`/`CancelAfterPublish`/`StatKillStore`/`FakeProvider`）、deterministic fault-barrier seam（`#[doc(hidden)] set_pre_traverse_hook`、op tag `"stat"`/`"open"`/`"read_dir"`）、in-process `TcpListener` MockServer（HTTP/WebDAV/git 非依存 fixture）、self-exec subprocess crash fixture（env guard + `process::exit` fail-closed）、temp git repo fixture（git CLI のみ）を挙げる。headless fixture の構築パターンは、git は CLI のみで work/bare/`file://` mirror/LFS/gitlink/symlink/secrets を構築し ambient global git-lfs 設定を fixture-local config で無効化、git 非存在時は `Option`/`None` で明示 skip、WebDAV/HTTP は `TcpListener` で request を capture し scripted response を返す in-process server、TLS は `MockTlsServer` fixture である。環境 flake の切り分け例として、`mise run test-msrv` 初回で無関係の `webdav::status_401_maps_auth_expired` が flake 失敗 → 単独・file 単位・lane 再実行で green を確認し正直に記録した。過去に webdav flake・LNK1102 の観測例もあり、Fail が出た場合は単独再実行で切り分ける方針である。Windows 環境の注意として、canonical path は `\\?\` prefix を持ち、git-for-windows は `:` 入り filename を U+F03A に変換、symlink 関連テストは開発者モード有効で実測し、Unix/macOS は多くの slice で未実測（NotRun）と明記される。`check-headless-deps` の負側境界は一時コピー fixture で検証する手法（`HEADLESS_CRATES`/`EXACT` を注入した `headless-neg.mjs` が検出 exit 1 を返すことを確認）で、本物の script は変更せず登録行追加のみとした。

### 文書間の齟齬・注意点

status drift が複数ある。ALIB-03・ALIB-04・ALIB-06 の plan/task 文書と asset-library task 文書は in-progress のままだが、対応する IR（alib-04-git、alib-06、asset-library）は completed で実測結果を持つ。ALIB-05 の IR も status in-progress だが Validation 節は全 lane Pass を記録している。ALIB-03 については IR が存在せず、plan/task も in-progress のまま — 実装完了の実績は確認できない。ALIB-02 の import IR は merge 後 backfill であり、検証結果は PR #220 本文の転記（再測定ではない）と自ら明記している。v5 snapshot compat slice と verified-import-wiring slice の IR は `audit_impl_record` で missing-section error が HEAD 時点の既存 baseline と記録されている。alib-01 の `test-msrv` 記録は文書内に新旧 2 表が併記されており、task5 時点は fail（`cargo-platform@0.3.3` が rustc 1.91 要求、main 由来）、task6（merge 後）は pass で、新しい方が最新実測である。test 数の drift は実測追従で修正された例があり、ALIB-02 の test-spec は `import.rs` を 15 tests と記述していたが PR #236/#256 の追加で実測 21、fault-injection followup で 25 に更新された。webdav tests は ALIB-06 時点 34 → fault matrix で 42（`cargo test --test webdav` 41 passed + identity encoding 個別 1 passed）に増加した。doc graph の pre-existing findings として、repo 全体に legacy invalid-id 系・broken relation・reciprocal warning の baseline があり、複数 slice で「新規 finding を増やさない」ことを判定基準とし既存不具合の修復はスコープ外とする扱いが繰り返される。編集境界外の残存簿記は後続の bookkeeping PR または Coordinator の merge 時判断に委ねる運用である。

## 適用対象

この知識は Synvelis の Asset Library サブシステム全体に影響する。具体的には `synvelis-library` クレート（AssetProvider 契約・Local/Project/Git/WebDAV provider・import pipeline・digest 分類）、`synvelis-workspace::library_ui`（headless Browser/Import UX）、`synvelis-app` の `syn.library.*` op surface、`synvelis-project` の snapshot/digest 互換層、および検証 Harness（fault matrix・evidence 台帳）が対象である。Ruviform の `ruviform-io-file::rooted` capability（`RootedDir`/`RootedFile`/`open_regular`/`read_dir_each`/`open_scoped_root`）は containment の正本実装として関連し、cache・catalog・preview の非正本 store 設計、verified import の commit 契約、evidence honesty の 2 軸分類は Asset Library 以外の provider 追加や import 系機能の拡張にも適用される。実 GPUI mount・実 provider/network/credential・実 OS/FS durability は外部 gate（synvelis#114、synvelis#91、synvelis#84 cross-gate 等）に残る未完了領域である。
